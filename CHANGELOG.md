# Changelog

## Pre-launch audit (post-Stage-15)

Full review of every stage's work against the demo spec plus a Supabase-backend-specific pass, before going live. Each fix below has its own unit or e2e test. See the "Pre-launch audit" summary delivered in-session for the full report, including items deliberately *not* fixed (pre-existing demo behavior, out of this pass's scope).

- **Fix**: `listToCampaign()` (`views/lists.js`) now awaits `addLeadsToCampaign()`'s result instead of using it directly. On the Supabase backend that function returns a Promise (an async insert), not a number — the toast read `[object Promise] leads added to the campaign` and the page navigated to the campaign view before the insert had actually landed.
- **Fix**: Marking a lead Do Not Contact (`setDnc(l,"dncontact",true)`, `features/leads.js`) now cancels its pending follow-ups on the Supabase backend too. The local backend always did this; the Supabase branch only ever patched the `leads` row and never touched `follow_ups`, so a DNC'd lead's follow-up stayed "pending" and kept showing as due/overdue.
- **Fix**: Same function's Supabase branch now mirrors the *entire* server patch into the in-memory lead (`Object.assign(l, flagPatch)`), not just the one toggled key. It already sent `dnc`/`dnt` to the server correctly when marking Do Not Contact, but the local `l.dnc`/`l.dnt` were left stale until the next reload.
- **Fix**: `audit()` (`core/session.js`) now catches its fire-and-forget `writeAuditLog()` call. That call was neither awaited nor caught — every mutation across the app (this one function is the audit call site for leads/CRM/admin/settings/campaigns) could throw an unhandled promise rejection if the audit-log write itself failed.
- **Fix**: `viewPrices`/`viewCommissions` gating (Stage 14) is now also applied to the CRM board's own page header and every column's stats row (`views/crm.js`) — a role with per-card money already hidden could still read the pipeline-wide "$X potential · $Y net · $Z weighted forecast" totals and each column's dollar figures.
- **Fix**: The "DEMO — everything runs in this page..." banner (`views/shell.js`) now only renders on the local backend (`BACKEND==="local"`) instead of unconditionally — it was simply false once a real Supabase backend is deployed, regardless of demo-login settings.
- **Fix**: The login screen's own "DEMO — sample users sign in..." banner and "Sample users' password is `demo1234`" hint (`views/login.js`) now follow the same `VITE_DEMO_LOGIN` gate the one-click sign-in buttons already use, instead of always rendering.
- **Investigated, not a bug**: `features/campaigns.js`'s `sendingCampaign()` references `openDlg`/`field`/`full`/`pretty`/`me` without importing them. This looked like a certain `ReferenceError` on static analysis, but it isn't — `main.js`'s `Object.assign(window, {...})` (plus a `window.me` live getter) deliberately exposes this entire surface globally, and an unqualified identifier not bound locally or via import still resolves against the global object at runtime, same as `core/util.js`'s own `pretty()` already relies on for bare `me`/`can`. Confirmed working via direct testing; left as-is rather than "hardened" with imports that would cut against this codebase's established (if unusual) cross-module pattern.
- **Flagged, deliberately not fixed** (matches the original demo's own behavior, not a rebuild regression — see the global "don't fix undocumented demo bugs" rule): CSV export (`exportCrm`) includes every price/commission column regardless of `viewPrices`/`viewCommissions`; the CRM filters dialog's price/commission range inputs are shown regardless of those permissions too; and a number of permissions (the entire "Competitions" group, plus `deleteLeads`, `assignLeads`, `editDnc`, `browserDialer`, `viewAttempts`, `createFollowUps`, `createTemplates`, `deleteCampaigns`, `assignCampaigns`, `exportReports`, `manageIntegrations`, `viewTeamMembers`) are defined and assignable in Admin → Roles but never actually gate anything, in the demo and in this rebuild alike.

## Stage 14 fixes

One entry per fix, in the order they were applied. Each has its own commit and its own test (see the commit history for exact file lists).

- **Fix**: Added `.hidden { display:none !important; }` to `styles.css`. The Leads filter panel and the custom-field "Options" textarea both toggled a `hidden` class that no rule ever backed, so toggling it had no visual effect; `!important` is needed because `.filters`/other layout classes set their own `display` at the same specificity.
- **Fix**: `visibleLeads()` (`features/activity.js`) now honors team scope the same way `canSee()` already did. A role with `viewTeamLeads` but not `viewAllLeads` (e.g. the seed's "Inside Sales Manager") couldn't see a teammate's own leads in any `visibleLeads()`-backed screen or export, even though `canSee()` — the check used for a single lead everywhere else — already granted it.
- **Fix**: Removed a stray extra `""` cell in `exportCrm()`'s per-deal row (`features/crm.js`), right after the "Overdue" value. It shifted every column from "Days in stage" onward one column to the right of its own header for every non-forecast export mode.
- **Fix**: `viewPrices`/`viewCommissions` are now actually enforced. Both permissions existed and were assignable but nothing ever checked them. Money is now hidden (independently — a role can have one without the other) on the CRM board's deal cards (`dealCard()`, `features/crm.js`), the deal page's financials (`views/deal.js`), and the CRM dashboard's KPIs/tables (`views/crmdash.js`).
